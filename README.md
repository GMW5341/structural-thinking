# Structural Thinking: 논리적 사고 프레임워크 논의

## 배경

의료인이 임상 경험에서 얻은 통찰을 체계적으로 축적하고, 사업 아이디어로 연결하기 위한 구조화된 사고 시스템에 대한 논의.

## 핵심 결론

### 1. 현실적 접근: 기존 도구 조합부터 시작

별도 시스템을 개발하기 전에, 기존 도구 조합으로 워크플로우를 먼저 검증한다.

```
Obsidian (메모 + 태깅 + 연결)
  + Granola / Otter.ai (대화 캡처)
  + Claude / ChatGPT (분석, 패턴 발견, 가설 검증)
```

### 2. 태깅 컨벤션 설계가 핵심

어떤 도구를 쓰든 태깅 체계가 좋으면 나중에 이식 가능하다.

**소스 태그** — 정보의 출처:
- `#source/reading` `#source/conversation` `#source/observation` `#source/experience`

**도메인 태그** — 분야:
- `#domain/medical` `#domain/business` `#domain/tech`

**사고 단계 태그** — 정보의 성숙도:
- `#stage/raw` → `#stage/pattern` → `#stage/hypothesis` → `#stage/validated`

**프레임워크 태그** — 적용한 분석 도구:
- `#framework/first-principles` `#framework/analogy` `#framework/inversion`

### 3. 구조화된 사고 프레임워크

메모에 적용할 수 있는 사고 도구들:

| 프레임워크 | 용도 | 핵심 질문 |
|-----------|------|----------|
| First Principles | 본질 파악 | "제거하면 안 되는 것은?" |
| Analogy Transfer | 영역 간 연결 | "A에서 작동하는 원리가 B에도 적용될까?" |
| Inversion | 위험 식별 | "이게 실패하려면 뭐가 필요할까?" |
| Constraint Analysis | 실현 가능성 | "법적/시간적/자원적 제약은?" |

### 4. 가설 평가 파이프라인

사업 아이디어를 체계적으로 걸러내는 단계:

```
관찰 → 패턴 인식 → 가설 생성 → 빠른 필터링 → 깊은 검증
                                    ↓
                              [Quick Filter]
                              - 시장 규모 > 임계치?
                              - 규제 장벽 통과 가능?
                              - 내 역량으로 가능?
                              - 기존 대비 10x 나은 점?
                                    ↓
                              [Deep Validation]
                              - 고객 인터뷰 5명
                              - MVP 비용/시간 산정
                              - 경쟁 우위 지속 가능성
```

### 5. 차별화 분석: Build vs Buy

| 기능 | 기존 제품 | 기존 도구로 충분? |
|------|----------|-----------------|
| 음성 → 구조화 | Granola, Otter.ai | O |
| 메모 + 연결 | Obsidian, Roam | O |
| AI 태깅/요약 | Notion AI, Mem.ai | O |
| 패턴 발견 | ChatGPT/Claude | △ (수동) |
| 능동적 패턴 발견 | **없음** | X |

**유일한 차별화 지점**: 축적된 메모에서 능동적으로 패턴을 발견하고 가설을 제안하는 시스템. 하지만 이것은 충분한 데이터(50~100개 메모)가 쌓인 후에 의미가 있다.

### 6. 실행 로드맵

```
지금 당장:     기존 도구 조합 (Obsidian + Claude)
              태깅 컨벤션 확정 후 메모 축적 시작

3~6개월 후:   메모 50~100개 축적
              수동 연결의 한계를 체감

그 후 결정:   기존 도구로 충분 → 그대로 유지
              한계 명확 → 능동적 패턴 발견 시스템 개발
```

## 핵심 원칙

> 도구를 먼저 만들면 **상상 속의 문제**를 풀게 된다.
> 먼저 써보면 **실제 문제**를 알게 된다.
